أريد بناء Web App احترافي وكامل باسم:

# El BAFFA

هذا النظام مخصص فقط لإدارة المنتجات والمبيعات داخل مكان يحتوي على 11 Room.

**ممنوع تمامًا ربط النظام أو تعديله أو الاعتماد على أي برنامج خارجي خاص بالبلايستيشن.**

النظام مستقل تمامًا، ووظيفته فقط:

* تسجيل المنتجات التي يتم طلبها في كل Room.
* حساب الكميات والأسعار.
* استخدام Barcode Scanner.
* إمكانية إضافة المنتجات بالضغط عليها.
* إدارة المخزون.
* إصدار الفواتير.
* حفظ المبيعات.
* التقارير.
* إدارة المستخدمين والصلاحيات.

# 3. Dark Mode و White Mode

يجب توفير وضعين كاملين:

### Dark Mode

واجهة داكنة احترافية باستخدام الأسود ودرجات داكنة، مع الأحمر كلون Accent.

### White Mode

واجهة فاتحة ونظيفة باستخدام الأبيض والأسود مع الأحمر كلون Accent.

يجب حفظ اختيار المستخدم بحيث عندما يغلق الموقع ويفتحه مرة أخرى يظل على الوضع الذي اختاره.

# 4. نظام تسجيل الدخول والأمان

الموقع **ممنوع أن يكون متاحًا لأي شخص بدون تسجيل دخول.**

أي شخص يفتح الموقع يجب أن تظهر له صفحة Login.

لا يمكن الوصول إلى Dashboard أو أي صفحة داخل النظام بدون Authentication.

أريد نظام Authentication حقيقي وآمن.

مثال المستخدم الأول:

اسم المستخدم:
Kimo

البريد الإلكتروني:
[kimo@elbaffa.com](mailto:kimo@elbaffa.com)

كلمة المرور:
900300

**مهم جدًا:**

لا تضع كلمة المرور بشكل مباشر داخل Frontend Code.

لا تضع كلمات المرور في JavaScript أو HTML أو ملفات عامة.

استخدم نظام Authentication حقيقي مع Password Hashing وSession Management.

كلمة المرور التجريبية المذكورة أعلاه تستخدم فقط لإنشاء المستخدم الأول أثناء إعداد المشروع، ويتم تخزينها بشكل آمن Hash وليس Plain Text.

يجب حماية جميع الصفحات والـRoutes.

إذا حاول شخص الوصول مباشرة إلى:

/dashboard
/products
/sales
/inventory

بدون تسجيل دخول، يجب تحويله تلقائيًا إلى صفحة Login.

* تسجيل الدخول.

# 21. حماية قاعدة البيانات

لا تعتمد فقط على إخفاء الصفحات في Frontend.

يجب تطبيق Authorization حقيقي على مستوى Backend / Database.

الموظف لا يستطيع إرسال Request يدويًا لتعديل سعر منتج أو حذف مبيعات أو تعديل المخزون إذا لم تكن لديه الصلاحية.

استخدم Row Level Security أو نظام صلاحيات مناسب حسب قاعدة البيانات المستخدمة.

---

# 22. منع مشاكل الـConcurrency

إذا كان أكثر من موظف يستخدم النظام في نفس الوقت، يجب ألا يؤدي ذلك إلى فقدان البيانات.

مثال:

موظف A يضيف Pepsi إلى Room 1.

موظف B يعمل Scan لمنتج آخر.

يجب أن تبقى البيانات صحيحة لكل Room.

وعند إغلاق الطلب، يجب تنفيذ تحديث الطلب والمخزون بطريقة آمنة تمنع خصم المخزون مرتين.

# 28. جودة الكود

أريد المشروع Production-Ready قدر الإمكان.

قبل الانتهاء:

* راجع جميع الملفات.
* تأكد من عدم وجود Syntax Errors.
* تأكد من عدم وجود Broken Imports.
* تأكد من صحة جميع Routes.
* تأكد من صحة Database Queries.
* تأكد من جميع Authentication Guards.
* تأكد من صلاحيات Admin وEmployee.
* تأكد من عدم وجود بيانات حساسة داخل Frontend.
* تأكد من عدم وجود API Keys أو Secrets مكشوفة.
* استخدم Environment Variables للأسرار.
* تعامل مع جميع حالات الخطأ.
* تأكد من عدم وجود Buttons وهمية لا تعمل.
* تأكد من أن جميع العمليات الأساسية تعمل فعليًا.

لا تكتفِ بإنشاء واجهة شكلية.

أريد تطبيقًا فعليًا يعمل مع Database وAuthentication حقيقيين.
